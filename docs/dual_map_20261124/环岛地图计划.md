## 二、核心修复与回放迭代调优结论

### 1. 消除 `launch` 硬编码 `high_timeout: 0.5` 拖尾 + 四级优先级仲裁（`stop > avoid > detection > follower`）
- **问题根因**：`line_follower_with_detection.launch.py` 硬编码覆盖了 YAML 中的 `high_timeout: 0.12`，导致每次数字转向结束后多锁死 `0.50s` 开环盲转；在 `fork_04` 终点前直道（数字 `8` 左后方紧摆红锥 #2）引发左转冲向红锥。
- **修复与调参**：
  - 删除 `launch` 硬编码覆盖，将 `turn_duration` 显式调为 `0.44s`（保证环岛分岔口足够切入角，同时过数字后 `0.12s` 即交还巡线）；
  - `cmd_mux_node` 升级四级仲裁：远场红锥（`risk < 0.28`）绝不干涉分岔/加分转向；近场高风险红锥或禁行区（`risk >= 0.28`）通过 `/cmd_vel_avoid` 平滑接管转向尾段。

### 2. 数字对齐逻辑回放验证与调优（`16 / 16` 高分数字 100% 命中，`0` 停车后误触发）
- **回放发现的关键跨模块细节**：
  - 在弯道入口（如 `2 vs 7`）或斜向进入（如 `5 vs 8`）时，外侧低分数字会比高分数字提前 `0.2~1.0s` 经过纵向对齐线！若改为“先筛对齐带再比大小”或下移对齐线，会被低分数字提前抢触发并进入冷却。
  - **最终逻辑与调参**：保留“**先在有效前视带 `cy ∈ [0.48, 0.72]` 内取全图最大面值数字 `chosen`，再等待该最大数字自身到达 `centroid_y ± 0.012`**”的核心顺序，叠加 `confidence_threshold: 0.35` 与 `start_cmd + yellow_line_detected` 双重静默门控。
  - **4 包实测结果**：`fork_01~04` 共 16 次数字交互全部精准命中最高面值 `[7, 7, 5, 8]`，终点 `END` 停稳后误触发降为 **`0` 次**。

### 3. 镂空红色禁行区（`1 cm` 细框 + 多竖纹）`35×13` 闭运算聚类 + 近端目标优先 + 柔和避让增益调优
- **回放调优**：
  - 原版 `3×3` 开运算打断细红框导致 4 包 `line=0`。新增多条纹（`>=2` 条独立红纹、填充率 `0.025~0.30`、扁平比 `>=1.30`、周围白路占比 `>=0.50`）`35×13` 闭运算聚类分支，完整框住整个禁行区；
  - 当近端禁行区与远端无害红锥同框时，按**更靠近车头（`line_bottom >= cone_bottom - 15`）优先**选择避障目标；
  - 根据禁行区左右两侧**真实白色路面宽度**决定绕行方向，并将 `red_line_soft_yaw` 从初版 `0.42` 回调至 **`0.28`**（动态放大后对应 `-0.28 ~ -0.71 rad/s`），既留足禁行区安全余量，又避免向右避让过猛压右侧黑边。
  - **4 包实测结果**：`fork_01~04` 每包稳定检出 `17~20` 帧完整红色禁行区，场外红衣/红电脑 `0` 误检。

### 4. PD 微分阻尼（`kd: 0.28`）
- 有效抑制绕过红锥与禁行区回正时的反抽摆尾，黄线停车、未启动及丢线恢复帧自动清零微分历史防冲击。
